# Rate-Based Index Forcing (RBIF)

## Context and Problem Statement

A dedicated module measures the rate at which the user is changing images,
the image-per-second (IPS) metric referred to in code, and based on this rate
makes a decision about what to show the user next.
Considering our second pillar of speed first, we have two scenarios:
- Low IPS: User is switching images at a managable pace, at which we can always
avoid a total cache-MISS.
- High IPS: User is very quickly switching past images, at a pace that the cache 
system cannot keep up with.

In the low IPS scenarios we respond with an Honest Index, that is we provide the 
following image according to the index established prior to the beginnning of the 
session. This behavior is the only available behavior in strictly-sorted slideshows.
Uniquely for randomly sorted slideshows, we have Forced Index as a response for 
high IPS scenarios, in which the provided landing image is dynamically defined by
the application, and shown to the user based on cache/thumbnail availability.
