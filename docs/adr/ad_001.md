# Image caching strategy

## Context and Problem Statement

As discussed in /docs/ARCHITECTURE.md images must be displayed faster than 100ms, that
amount of time is the expected duration of the "next image animation", thus allowing
us to occlude the canvas for that period. Any transition from a  black canvas to a 
colorful image would be felt by the user, thus we conceal with animation, and optimize
to ensure compliance with the duration limits of the animations.
To provide such speeds in most scenarios a robust caching/loading strategy is necessary.

Minimizing consumed resources is paramount since Iteradraw is meant as an art companion
app, intended to run alongside resource intensive applications. 
The center of the UX in Iteradraw is the image load speed, as users truly expect only
one thing: an image, on screen, fast.

## Considered Options

### Stacked cache:
Multiple layered caching strategies employed to minimize memory footprint, maintaining
fast load speeds.

Discussion:
* Excepting only scenarios where the user possesses very large images exclusively,
in which case only the L4 dynamic Cache may expand to meet its oblication of holding
the full-size, full resolution, version of only the current image for zooming functionality.

### Streaming pipeline:
Stream decoded bytes to a pixel buffer in VRAM, decode images progressively.
(rejected)

Discussion:
* Fast As Fuvk boiiii

Why rejected:
* This solution if far too resource intensive.

## Decision Outcome

A stacked caching strategy layered as follows:

* L1 Cache: VRAM cache (for dGPU systems)/RAM cache (for iGPU) dedicated to textures.
* L2 Cache: RAM cache for 2048px (2K) thumbnails for fast upload.
* L3 Cache: OS-managed cache using mmap for quick, no-waste on-the-fly decodes.
* L4 Cache: Dynamic RAM cache for the following purposes:
    * Caching frequently accessed "Favorites" (LFU strategy);
    * Caching Highest-quality version of the current image for zoom-action:
    * Preloading distant images into thumbnails for quick decode in high IPS,
  Honest-Indexing-only slideshows.
